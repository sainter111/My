# 통화·메시지 → 캘린더 등록

사용자(대표)의 통화 녹취록이나 메시지 내용을 분석해 할 일을 추출하고, 승인을 받아 구글 캘린더에 등록한다.

## 운영 원칙

1. **제안 후 승인받고 등록한다.** 분석 결과와 제안 시각을 먼저 보여주고, 사용자가 고른 항목만 등록한다. 승인 없이 캘린더를 바꾸지 않는다.
2. **업무 시간 기준은 평일 09:00~18:00.** 주말과 공휴일에는 일정을 제안하지 않는다. 단 사용자가 그 날에 하겠다고 하면 따른다.
3. **타임존은 항상 `Asia/Seoul`.**
4. **캘린더 ID는 `pch5509@gmail.com`** (기본 캘린더).

## 1단계 — 파일 읽기

한글 파일은 대부분 **CP949(EUC-KR)** 인코딩이라 그냥 읽으면 깨진다. 반드시 변환한다.

```bash
iconv -f CP949 -t UTF-8 "<파일경로>"
```

`file <파일경로>` 결과가 `ISO-8859 text`로 나오면 CP949다. UTF-8이면 그대로 읽는다.

에이닷 통화 녹취 파일의 형식:

```
에이닷 전화

<연락처명>(<전화번호>) 님과의 통화
2026. 9. 22.(화) 09:49
2분 53초

[녹음 내용]
상대방 00:00
<발화>

나 00:02
<발화>
```

`나` = 사용자(대표), `상대방` = 통화 상대.

## 2단계 — 할 일 추출

추출한 각 항목마다 다음을 분리해서 적는다.

| 항목 | 내용 |
|---|---|
| 할 일 | 무엇을 하는지 |
| **실행 주체** | 사용자 본인인지, 상대방/직원인지 |
| **사용자 몫** | 본인이 직접 하는 일인지, 남이 하는 일을 확인·독촉하는 일인지 |
| 기한 | 통화에서 언급된 시점, 없으면 추정 근거를 밝힘 |
| 선행 조건 | 다른 항목에 막혀 있으면 표시 |

주체를 섞지 않는 것이 중요하다. 사용자는 본인이 직접 할 일만 캘린더에 넣고 싶어할 수 있고, 남이 할 일은 "확인·독촉" 성격으로만 넣고 싶어할 수 있다. **어느 쪽을 등록할지 반드시 물어본다.**

## 3단계 — 음성인식 오류 표시

녹취록은 자동 음성인식 결과라 오인식이 잦다. 확실하지 않은 부분은 **판독 주의 사항**으로 따로 모아 제시하고, 추측한 원문을 병기한다.

실제로 겪은 예:
- 회사명·사람 이름이 뭉개짐 ("신일랑" → "신라"?)
- 같은 단어가 다르게 인식됨 ("모델 / 모듈 / 모딜")
- 발음이 비슷한 다른 단어 ("지워줘야지" → "쥐어줘야지", "메일 파갖고" → "내일 파갖고")
- 문장이 통째로 깨져 뜻이 안 잡히는 구간

숫자(금액, 소요 시간, 날짜)는 특히 신뢰하지 말고 "확인 필요"로 표시한다.

## 4단계 — 캘린더 확인 (등록 전 필수)

제안 시각을 정하기 **전에** 반드시 기존 일정을 읽는다. 이걸 건너뛰면 출장 중인 날에 사무실 일정을 제안하는 실수가 난다.

```
mcp__Google_Calendar__list_events   # pch5509@gmail.com, 해당 기간
mcp__Google_Calendar__list_events   # ko.south_korea#holiday@group.v.calendar.google.com
```

공휴일 캘린더 ID: `ko.south_korea#holiday@group.v.calendar.google.com`
(연휴 날짜를 기억이나 추측으로 계산하지 말고 반드시 조회한다. 추석·설은 매년 바뀐다.)

확인할 것:
- **출장·외출 종일 일정** — 그 날 사무실 작업은 제안 불가
- **공휴일·연휴 범위** — "연휴 전 마감"이 실제로 며칠인지
- **뒤에 있는 회의** — 준비물의 실제 마감 시점을 결정함
- **이미 등록된 중복 일정**

## 5단계 — 제안

표로 제시한다. 각 줄에 **제안 시각 / 소요 시간 / 그 시각인 근거**를 넣는다. 근거는 앞뒤 일정과의 관계로 쓴다 ("출장 출발 전", "이 파일이 없으면 다음 작업이 막힘", "회의 전날").

제약 조건도 함께 보여준다.

```
9/23(수)  오늘 · 부산 이동 · 연휴 전 마지막 근무일
9/24(목)  추석 연휴 시작
...
9/29(화)  12:00 조달회의  ← 준비물 필요 시점
```

그 다음 `AskUserQuestion`으로 고르게 한다. 항목이 많으면 "본인이 직접 할 일"과 "확인·독촉할 일"로 질문을 나눈다.

## 6단계 — 등록

`mcp__Google_Calendar__create_event`로 승인된 항목만 만든다.

- `calendarId`: `pch5509@gmail.com`
- `timeZone`: `Asia/Seoul`
- `summary`: `[주체/성격] 할 일` 형식 — 예) `[대표] 규격 도면 재전송`, `[전화] 샘플 전달 독촉`, `[확인] 카탈로그 수신`
- `description`: 배경, 선행 조건, 그리고 **출처를 반드시 마지막 줄에** 남긴다
  ```
  출처: 9/22(화) 09:49 통화 · 010-6527-6881
  ```
- `overrideReminders`: 중요한 건 30분 전, 보통 10분 전, 짧은 확인은 5분 전
- 선택되지 않은 항목은 등록하지 않는다. 앞서 만든 게 있으면 `delete_event`로 지운다.

### 알려진 함정 두 개

**종일 일정의 날짜가 하루 밀린다.** `allDay: true`로 만들 때 `startTime`을 `2026-09-23T00:00:00+09:00`으로 주면 UTC로 환산(9/22 15:00Z)되어 **9/22에 등록된다.** 정오 기준 시각을 줘야 한다.

```
startTime: 2026-09-23T12:00:00+09:00   # → 9/23 종일
```

등록 후 `list_events`로 날짜를 확인한다.

**`description`에 HTML 엔티티를 쓰면 그대로 저장된다.** `&#10;` 같은 걸 쓰지 말고 실제 개행 문자를 넣는다.

## 7단계 — 검증

등록이 끝나면 `list_events`로 해당 기간을 다시 읽어 확인한다.

- 요청한 시각·날짜대로 들어갔는지
- 중복이 생기지 않았는지 (거절된 도구 호출이 실제로는 실행됐을 수 있다)
- 기존 일정과 겹치지 않는지

그리고 최종 상태를 표로 보고하고, **의존 관계 흐름**을 함께 보여준다.

```
오늘 13:00 도면 전송  →  직원 가공 착수 가능
오늘 18:00 카탈로그 수신 ─→ 9/27 카탈로그 작업 → 9/29 조달회의
```

## 함께 남기면 좋은 것

사용자가 원하면 구글 드라이브에 메모를 문서로 저장한다 (`mcp__Google_Drive__create_file`, `contentMimeType: text/plain` → 구글 문서로 변환됨). 폰에서 열람·수정이 되고 체크리스트로 쓸 수 있다.

구글 킵은 커넥터가 없어 직접 저장이 불가능하다. 드라이브 문서나 붙여넣기용 텍스트로 대체한다.
